# 7단계 — 단가표 업로드 파서

관리자가 SKT 단가 개정 파일(xlsx)을 앱에 업로드하면 `내역서_일반`/`자재내역서_일반`
시트를 읽어 `labor_price_master`/`material_price_master`에 반영한다.

## 구성

- **`XlsxReader`** (`data/excel`) — Apache POI 없이 `java.util.zip` + 표준 SAX 파서만으로
  xlsx(zip+XML)에서 지정한 시트 이름의 셀 값을 읽는 경량 리더. workbook.xml → 시트
  이름/관계 ID 매핑 → workbook.xml.rels → 실제 시트 파일 경로 → sharedStrings.xml
  해석까지 처리한다. (엑셀 **읽기**만 필요한 단계라 POI 없이도 충분 — POI 도입 여부는
  9단계 엑셀 **생성** 엔진에서 별도로 검토)
- **`PriceMasterParser`** (`data/excel`) — [02_price_master_schema.md](02_price_master_schema.md)
  문서의 열 매핑(내역서_일반: C/D/E/F/G/H/O/P/Q, 자재내역서_일반: C/D/E/F/G/H/L)대로
  행을 `LaborPriceMaster`/`MaterialPriceMaster`로 변환한다. 공정번호/자재코드 열 값이
  숫자로만 이루어진 행만 데이터로 인식해서 헤더 행을 자동으로 걸러낸다.
- **`PriceUploadActivity`** — 현장 목록 화면(`MainActivity`) 툴바 메뉴의
  "단가표 업로드"로 진입. 적용 연도 입력(기본값 2026) → 파일 선택(`GetContent`) →
  업로드 시 캐시에 복사해 파싱 → `labor_price_master`/`material_price_master`에
  upsert(REPLACE) → `price_upload_history`에 기록. 화면 하단에 업로드 이력을 보여준다.

## ✅ 실제 2026년 파일로 컬럼 매핑 검증 완료

`26년 대구P` 폴더에서 찾은 이번 사업 현장(JP13464)의 2026년 실제 정산 파일은
사내 문서보안(DRM, 매직바이트 `SCDSA004`)으로 암호화돼 있어 처음엔 열어볼 수
없었지만, 이후 사용자가 DRM이 해제된 사본 두 개를 직접 업로드해줘서 실제
"내역서_일반"/"자재내역서_일반" 시트 원본을 확인할 수 있었다.

`XlsxReader`와 동일한 방식(SAX 파서로 workbook.xml → 시트 매핑 → sharedStrings.xml
해석)으로 실제 셀 값을 직접 뽑아본 결과, 아래처럼 문서(02단계)에 적어둔 예시 값과
**한 글자도 틀리지 않고 정확히 일치**했다:

| 필드 | 열 | 실제 파일 값 | 문서 예시 |
|---|---|---|---|
| 공정번호 (내역서_일반) | E6 | `11773` | `11773` |
| 구분 | C6 | `추가할증` | `추가할증` |
| 공종 | D6 | `선로-1.케이블 포설` | `선로-1.케이블 포설` |
| 공종명칭 | F6 | `14-5-1-1. 광케이블 포설(소규모할증 500m이하)` | 동일 |
| 규격 | G6 | `지중관로 케이블 포설` | 동일 |
| 단위 | H6 | `m` | `m` |
| 직접노무비 단가 | P6 | `4395` | `4395` |
| 자재코드 (자재내역서_일반) | C5 | `12754` | `12754` |
| 분류 | D5 | `케이블` | `케이블` |
| 자재명 | E5 | `광케이블` | `광케이블` |
| 규격 | F5 | `관로` | `관로` |
| 규격상세 | G5 | `12` | `12` |
| 자재단가 | L5 | `679` | `679` |

→ **`PriceMasterParser`의 컬럼 상수(LABOR_COL_*, MATERIAL_COL_*)는 그대로 실사용
가능하다.** 숫자 코드 열로 헤더 행을 걸러내는 방식도 그대로 유효 (헤더 행은 해당
열에 한글 라벨이 들어있어 자동으로 제외됨).
