# 10단계 — `기별` 구간 데이터 입력

> 실제 2026년 JP13464 파일의 `기별` 시트를 직접 열어본 분석을 바탕으로 계획을
> 세우고, 그 계획대로 입력 화면(`RouteSegmentEditActivity`)까지 구현했다.
> 아직 안 한 것은 "엑셀에 실제로 써넣기"(→ 11단계, `기별` 시트 컴포저)뿐이다.

## 1) `기별` 시트가 실제로 무엇인가

`내역서_일반`/`자재내역서_일반`의 수량은 사람이 직접 입력하는 게 아니라
`기별` 시트를 SUMPRODUCT 수식으로 집계한 결과다 (07단계 문서 참고). `기별`은
**126개 열(A~DV)** 짜리 시트지만, 실제로는 아래처럼 계층적으로 구성돼 있다:

- 5~8행: 126개 열을 15개 공정 대분류(조가선 포설/부대공사/광케이블 포설/
  케이블 보호/포박·해체/접속/성단 및 시험/안전/전주건식/기타/업무지원/FTTH/
  선번DB현행화/추가/5G-PON)로 묶은 계층 헤더. 즉 **열 구조 자체가 단가표의
  공정 분류를 그대로 옮겨온 것**이다.
- 9행: 파일 전체 요약(공사명 등) — `SiteCase`와 중복되는 정보.
- **11행부터: 진짜 데이터.** 한 행 = "전주 하나(구간 지점)에서 있었던 일
  전부"를 가로로 펼쳐놓은 것. 예:
  ```
  row 13: D13=[학산간20R1] H13=[60] I13=[60](누적거리)
          AB13=[신규] AC13=[Dry] AD13=[144] AE13=[가공] AF13=[신설]
          BB13=[보조20] BC13=[1] BD13=[주간] BE13=[가공] BF13=[D-외피추가] BG13=[1] BH13=[방호차]
  ```
  → "학산간20R1 전주까지 60m 구간, Dry 144코어 신규 가공케이블 신설, 접속
  부자재(보조20) 1개, 주간 작업, 접속구분 D-외피추가, 방호차 사용"

이번 실제 파일(불량함체_7929DX01/JP13464)에서 데이터가 있는 행은 **11~27행,
17줄뿐**이었다 (28행 이후는 수식이 0을 보여주는 빈 템플릿 자리). 즉 한 현장당
보통 15~30개 구간 정도의 규모로 보인다.

## 2) 왜 지금 모델(`CableItem`)로는 부족한가

6단계에서 만든 `CableItem`은 "케이블 한 조 전체"를 한 행으로 본다
(예: 기설케이블#1 643M, 가입자망, 48C/39C). 반면 `기별`은 그 케이블 한 조를
**전주 구간별로 쪼개서** 기록한다 (위 예시처럼 같은 케이블이라도 구간마다
길이/작업 내용이 다르게 한 행씩 생긴다). `CableItem`은 ENG시트 요약 문구를
만드는 데는 맞지만, `기별`(→ 원가계산 자동화)에는 세분화가 부족하다.

또한 두 개의 서로 다른 축이 섞여 있다는 점이 중요하다:
- **AB열 "신규/재고"**: 이 구간에 쓰는 *자재*를 새로 사는지, 창고 재고를
  쓰는지 (회계/자재관리 관점) — 특별한 계산/파생 로직이 아니라 사용자가
  구간마다 직접 고르는 단순 2지선다 항목이다 (라디오버튼 하나면 됨).
- **AF열 "신설/철거"**: 이 구간에서 실제로 하는 *공사*가 설치인지 철거인지
  (공사 관점) — 기존 `FacilityPhase`(EXISTING/NEW) enum을 그대로 재사용

이 둘은 서로 독립적인 값이라 각각 별도의 라디오 버튼으로 입력받는다.

## 3) 구현한 입력 UX (`RouteSegmentEditActivity`)

126개 열을 그대로 화면에 옮기면 절대 못 쓴다. 그래서:

1. **"구간 추가" 리스트 화면** (6단계 체크리스트의 케이블/함체 행 추가와 같은
   패턴) — 현장 하나에 구간을 여러 개 순서대로 추가. 각 카드 상단에 "구간 #1"
   처럼 순번을 자동으로 매겨서 보여준다 (`renumberRows`).
2. 구간 하나의 **기본 입력**(항상 보이는 필드): 전주명, 구간거리(m),
   신규/재고(라디오), 신설/철거(라디오), 케이블종류, 코어수, 가공/지중(라디오).
   - **누적거리는 입력받지 않는다** — 원래 계획대로, 저장할 때 순서(seq)만
     남겨두고 필요할 때(11단계 엑셀 내보내기) 이전 구간 길이를 누적 합산해서
     계산한다. 사람이 계산 실수할 일을 하나 없앴다.
3. **선택 입력(있을 때만 추가)**: 각 카드에 "+ 접속 정보"/"+ 안전 정보" 버튼이
   있고, 눌러야 해당 구간에 접속구분/주야/방호차 필드가 펼쳐진다 — 실제로 그
   작업이 없는 구간은 기본 항목만 입력하면 끝. 나머지 90여 개 열(조가선/
   전주건식/5G-PON 등, 지장이설 사업에서는 거의 안 쓰는 그룹)은 이 앱 범위에서
   아예 제외했다.

## 4) 데이터 모델 (구현 완료)

```kotlin
enum class StockType { NEW, STOCK }        // 신규 / 재고 — 사용자가 직접 선택
enum class LayingMethod { AERIAL, UNDERGROUND }  // 가공 / 지중 — 사용자가 직접 선택

@Entity(tableName = "route_segment")
data class RouteSegment(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val siteCaseId: Long,
    val seq: Int,                     // 구간 순서 (누적거리 계산 기준)
    val poleName: String,             // 전주번호/지점명 (예: 학산간20R1)
    val segmentLengthM: Double,       // 구간거리
    val stockType: StockType,         // 신규/재고 선택 (AB열)
    val workType: FacilityPhase,      // 신설/철거 — 기존 enum 재사용, 선택 (AF열)
    val cableType: String?,           // Dry 등 (AC열)
    val coreCount: Int,               // 코어수 (AD열)
    val layingMethod: LayingMethod,   // 가공/지중 선택 (AE열)
    // 아래는 선택 입력 — 해당 없으면 null
    val spliceType: String? = null,   // 접속구분 (BF열, 예: D-외피추가)
    val workShift: String? = null,    // 주/야 (BD열)
    val needsGuardTruck: Boolean = false // 방호차 (BH열)
)
```

(`StockType`/`LayingMethod`는 기존 `FacilityPhase`/`RouteType`과 같은 패턴으로
`Converters`에 `TypeConverter`를 추가했다. 새 엔티티 추가로 DB 버전을 1→2로
올리고 `fallbackToDestructiveMigration()`을 적용했다 — 아직 배포 전이라 기존
로컬 데이터 보존보다 개발 편의를 우선했다.)

→ 이번엔 이 한 건의 실제 사례만 보고 필드를 확정했다. 나중에 신설/철거 위주가
아닌 다른 성격의 현장 파일을 보게 되면 필드를 더 추가/조정할 수 있다 (지금
구조는 새 선택 항목 그룹을 추가하기 쉬운 형태로 만들어뒀다).

## 5) 기존 기능과의 관계

- `CableItem`/`EnclosureItem`(6단계, ENG시트 요약용)은 **그대로 둔다** — 이미
  만들어서 검증한 걸 건드리지 않는다. `RouteSegment`는 원가계산 자동화만을
  위한 **별도의 추가 입력**으로 둔다 (같은 정보를 두 번 입력하는 건 아쉽지만,
  기존 화면을 다시 뜯어고치는 것보다 리스크가 적다). 나중에 여유가 되면
  `RouteSegment` 목록에서 `CableItem` 요약을 자동 생성하는 것도 검토 가능.
- 엑셀에 실제로 써넣는 부분은 9단계에서 이미 만든 `XlsxCellPatcher`를
  그대로 재사용한다 — `기별` 시트도 결국 "셀 주소 → 값" 매핑만 있으면 되므로
  새 인프라가 필요 없다. 새로 필요한 건 (1) 위 입력 화면, (2) `RouteSegment`
  → `기별` 셀 매핑 컴포저뿐이다.
