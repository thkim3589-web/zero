# 3단계 — 엑셀 템플릿 셀/앵커 매핑

원본 샘플(`불량함체_월배간102(달서구JP13464)`)을 직접 파싱해서 확인한
실제 셀 주소 기준. 시트명은 프로젝트마다 동일(템플릿 고정)하다고 가정.

## 2) `공문 및 사진` — 사진 삽입 매핑

반복 패턴 확인됨 (블록당 3장, 39행 간격):

| 블록 시작행 | 슬롯1 (열 B~H) | 슬롯2 (열 K~Q) | 슬롯3 (열 T~Z) |
|---|---|---|---|
| 77 | 현장사진#1 | 현장사진#2 | 현장사진#3 |
| 116 | 현장사진#4 | 현장사진#5 | 현장사진#6 |
| 155 | 현장사진#7 | 현장사진#8(가변) | ... |

- 라벨 셀: `사진유형`/`제목` (블록 시작행), `사진설명`/`설명` (블록 시작행+1)
- 실제 사진: 블록 시작행+2 부터 약 23행 높이의 영역에 이미지 앵커
  (실측: col1→8·col10→17·col19→26, row 40→62 형태의 twoCellAnchor)
- 상단(행 38~39)에는 공문(허가서/요청서 스캔본) 삽입 영역이 별도로 존재

→ 앱에서는 사진 슬롯을 "3장 1세트" 반복 리스트로 입력받고, 각 사진에
유형/설명 텍스트를 붙여 저장. 내보낼 때 슬롯 순서대로 같은 크기 비율로
리사이즈해서 해당 앵커 위치에 삽입.

## 3) `개황도(전)` / `개황도(후)` — 지도+선 캔버스 매핑

이 시트는 사실상 "빈 캔버스"이며 셀 자체에는 데이터가 거의 없음. 대신:

- **배경 지도 이미지**: 가장 큰 그림 1장이 `col 0~35, row 20~89` 범위를 차지함.
  이 그림은 `descr`(원본 파일 경로)가 없음 → **클립보드 캡처 붙여넣기**라는 뜻.
  (반면 아래 범례 아이콘들은 `descr="D:\업무폴더\범례도\일반기설.gif"` 등
  실제 파일 경로가 남아있어 고정 리소스임을 확인)
- **범례 아이콘(작은 그림)**: "일반기설", "함체신설" 등 약 70여 개 — 케이블/함체
  상태를 표시하는 작은 마커. 고정된 아이콘 세트이므로 앱에서도 동일 아이콘
  리소스를 내장해서 재사용 가능.
- **케이블 경로 선**: 자유형 도형(custGeom) 30개 + 직선(line) 16개 —
  전부 배경 그림과 같은 `col 0~35, row 20~89` 좌표계 안에 겹쳐서 그려짐.

**앱 설계에 대한 결론**:
- 지도 SDK는 쓰지 않는다 — 실제 관로/전주/케이블 위치는 사내 GIS에만 있으므로,
  담당자가 GIS 화면을 캡처한 이미지를 앱에서 불러와 배경으로 쓴다.
- 캔버스 영역의 셀 좌표계(col/row/offset) 대신, 앱에서는 **불러온 이미지 기준
  상대좌표(0.0~1.0)**로 선의 점을 저장한다 (`BaseMapImage` + `RouteLine` +
  `RoutePoint`, 4단계 데이터 모델 참고). 화면 크기/배율이 달라도 그 이미지
  안에서는 항상 같은 위치를 가리키므로 어긋나지 않는다.
- 엑셀로 내보낼 때는, 불러온 배경 이미지 위에 저장된 상대좌표 점들을 이어
  선을 그린 합성 비트맵을 만들어서, 위 앵커 범위(`col 0~35, row 20~89`)에
  그림 1장으로 삽입한다. (범례 아이콘은 필요 시 같은 방식으로 합성 이미지에
  함께 그려 넣거나, 별도 고정 아이콘으로 얹는다)
- `개황도(후)` 시트도 동일 구조 (전/후 두 장 = 이설 전/후 상태를 각각 저장)

## 4) 원가계산 관련 시트 (`내역서_일반`/`자재내역서_일반`/`원가계산서(일반)`)

→ [02_price_master_schema.md](02_price_master_schema.md) 문서의 열 매핑표로 대체.
(공정번호/자재코드를 키로 마스터 단가를 조회해서 O/P/Q열, L열에 채우고,
원가계산서(일반)는 그 합계를 SUM/비율식으로 자동 계산 — 이미 시트 내 수식이
처리하므로 앱에서는 수량 값만 정확한 셀에 넣으면 됨)

## 남은 확인 사항
- `개황도(후)` 시트가 `개황도(전)`과 완전히 동일한 앵커 좌표 체계인지 재확인 필요
  (2단계 진행 중 확보 예정인 실제 최신 템플릿으로 재검증)
- 사진 슬롯 개수가 현장마다 가변적임(위 예시는 최소 7장 이상) → 블록을
  필요한 만큼 반복 삽입하는 로직 필요 (자바 POI로 행 복제 방식 검토)
