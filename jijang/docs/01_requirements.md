# 1단계 — 요구사항 및 MVP 범위 확정

## 배경
현재 지장이설(불량함체 개선 등) 현장 작업 결과는 SKT 표준 정산 엑셀 템플릿
(예: `불량함체_월배간102(달서구JP13464)_...xlsx`, 35개 시트)에 수기로 작성되고 있음.

문제점:
1. 현장 체크리스트/사진/지도 자료를 PC 엑셀에서 수작업으로 채워 넣어야 함
2. 지도 위에 케이블 경로(선)를 그릴 때, 매번 GIS 화면을 캡처해서 붙여넣기 때문에
   배경 이미지의 축척·중심좌표가 매번 달라져 기존에 그려둔 선과 어긋남
3. 원가계산에 필요한 단가(내역서_일반/자재내역서_일반)가 프로젝트 파일마다
   하드코딩되어 있어, SKT 단가 개정 시 매 건마다 수작업 갱신 필요

## 목표
현장에서 모바일로 데이터를 입력하면, 위 엑셀 템플릿과 동일한 형식의 결과물을
자동으로 생성한다.

## MVP 범위 (1차 버전)

포함:
- [x] 현장 체크리스트 입력 (ENG시트 Checklist 대응)
- [x] 현장 사진 촬영/첨부 (공문 및 사진 대응)
- [x] 지도 위 케이블 경로 선 그리기 — **좌표(위경도) 기반 벡터로 저장**,
      점 추가/이동/삭제로 언제든 재편집 가능 (개황도 전/후 대응)
- [x] 원가계산 자동화 — 단가표/요율표를 마스터 데이터로 관리하고,
      현장 입력 수량 × 단가로 내역서/자재내역서/원가계산서 자동 계산
      (SKT가 단가를 개정하면 관리자가 최신 단가 파일을 업로드해서 갱신)

1차 제외 (추후 확장 검토):
- [ ] 직선도(전/후) — 실측 지도가 아닌 흐름도 형태 스키매틱 자동 생성
      (도형 배치 로직이 복잡하여 별도 단계로 분리)
- [ ] 실시간 GIS 연동 (한전/SKT 내부 GIS 시스템과의 직접 연동)
- [ ] TANGO 시스템 자동 업로드 연동

## 플랫폼/기술 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 모바일 플랫폼 | 안드로이드 네이티브 (Kotlin) | 기존 골프 야디지 앱과 동일 스택 |
| 지도/배경 | **지도 SDK 미사용 — GIS 캡처 이미지를 앱에서 불러와서 사용** | 실제 시설물(관로/전주/케이블) 위치는
      Google Maps/카카오맵 등 공개 지도에는 없고 사내 GIS 시스템에만 있으므로,
      담당자가 GIS 화면을 캡처한 이미지를 앱으로 불러와 그 위에 선을 그리는 방식으로 결정 |
| 데이터 저장 방식 | **앱 내 로컬(SQLite/Room)** | 소수 인원이 사용하는 현장 도구 특성상 서버 인프라 없이
      단순하게 시작. 단가 마스터도 로컬 DB에 저장하고, 관리자가 파일을 업로드하면
      로컬 DB를 갱신하는 방식 |
| 엑셀 생성 | **앱 내 On-device 생성 (Apache POI for Android)** | 서버 없이 폰에서 바로
      템플릿 기반 xlsx 파일을 생성 → 카카오톡/이메일/드라이브 등으로 공유 |
| 선(경로) 저장 방식 | **불러온 GIS 이미지 기준 상대좌표(0~1) 리스트** (벡터), 내보낼 때만 이미지 위에 선을 그려 합성 | "지도 배경이 매번
      바뀐다" 문제의 근본 해결책 — 좌표가 위경도가 아니라 특정 이미지에 종속된 상대좌표이므로,
      그 이미지에 대해서는 화면 크기/배율과 무관하게 항상 정확히 맞는다 |

> 참고: 데이터 저장/엑셀 생성을 로컬로 결정한 것은 기본값(추천)입니다.
> 추후 여러 현장 인원이 단가 마스터를 동시에 공유해야 하거나, 여러 기기 간 동기화가
> 필요해지면 서버(백엔드) 방식으로 전환 검토.

## 참고: 분석한 원본 엑셀 구조 요약
- 35개 시트 중 MVP 대상: `ENG시트(Checklist)`, `공문 및 사진`, `개황도(전)`, `개황도(후)`,
  `내역서_일반`, `자재내역서_일반`, `원가계산서(일반)`, `탱고원가_일반`
- 외부링크 88개 중 실제 계산에 쓰이는 것은 없음 (전부 레거시 잔재, 라벨 캐시값 5개 제외)
- 원가계산서 수식은 전부 로컬 SUM/비율계산으로 완결됨 → 자동화 난이도 낮음
