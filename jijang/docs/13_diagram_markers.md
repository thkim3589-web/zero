# 13단계 — 개황도 함체/전주 마커 + 신설·철거 선 구분

5단계에서 만든 개황도 편집 화면은 "선 하나 + 이름 없는 점들"만 지원했다.
실제로는 함체 위치도 표시해야 하고, 신설/철거 구간을 색으로 구분해서 그려야
한다는 지적을 받아 아래처럼 확장했다.

## 핵심 설계 결정

새 아이콘 라이브러리를 만들지 않고, **이미 입력해둔 데이터를 재활용**한다:
- 함체 마커 → 6단계 체크리스트에서 입력한 `EnclosureItem` 목록에서 선택
- 전주 마커 → 10단계 구간별 상세에서 입력한 `RouteSegment.poleName` 목록에서 선택
- 접속점 마커 (실기기 테스트 피드백으로 추가) → 10단계 구간별 상세에서
  "+ 접속 정보"를 채운 구간들(`spliceType != null`) 목록에서 선택

이러면 지도 위에서 이름을 또 타이핑할 필요가 없고, 데이터가 이미 서로
연결되어 있다. 진짜 범례 아이콘(원본 gif 파일, 70여 개)은 실제 파일이 없어서
재현하지 않고, 대신 모양(원/사각형/삼각형)+색+텍스트 라벨로 단순하게
구분한다.

## 데이터 모델 변경

- `RoutePoint`에 `markerType`(`PLAIN`/`ENCLOSURE`/`POLE`/`CONNECTION`)과 `label`(지정
  시점 스냅샷 문자열) 추가. 재조회 없이 그릴 때 바로 쓰도록 이름을 그 자리에서
  복사해서 저장한다 — 나중에 원본 함체/전주 정보가 바뀌어도 지도의 라벨은
  그대로 남는다 (트레이드오프지만 훨씬 단순함).
- `RouteLine`은 이미 `lineLabel`/`colorHex`가 있었지만 화면에서 안 쓰고
  있었다 — 이번에 실제로 연결: `FacilityPhase.EXISTING`=철거선(빨강,
  lineIndex 0), `FacilityPhase.NEW`=신설선(파랑, lineIndex 1)로 고정 매핑.
  이미지 한 장에 최대 두 줄까지 지원한다.
- DB 버전 2 → 3, `fallbackToDestructiveMigration()` 유지.

## 화면 변경 (`DiagramEditActivity`/`RouteEditorView`)

- 상단에 "철거선 편집"/"신설선 편집" 토글 버튼 추가 — 편집 중이 아닌 쪽 선은
  반투명 참고선으로 배경에 같이 표시된다 (터치에는 반응 안 함).
- 빈 곳을 탭하면 바로 점이 추가되는 대신, **"일반 경로점 / 함체 위치로 지정 /
  전주 위치로 지정"** 선택 다이얼로그가 뜬다. 함체/전주를 고르면 목록에서
  선택 → 그 이름이 붙은 마커가 찍힌다 (원이 아니라 사각형/삼각형 + 라벨).
- 함체/전주/접속점 목록이 비어있으면(아직 체크리스트/구간을 안 채웠으면)
  안내 다이얼로그를 띄운다 — 처음엔 토스트로 만들었는데 실기기 테스트에서
  "지정이 안 된다"는 오해를 샀다 (토스트가 순간 지나가서 원인을 못 봄).
  확인 버튼 누를 때까지 남아있는 다이얼로그로 바꾸고, 조용히 일반 점으로
  대체하던 것도 없앴다 — 목록이 비면 그냥 아무 점도 안 찍힌다.

## 엑셀 내보내기 반영

`DiagramCompositor.composite()`가 이제 여러 줄(신설/철거)을 각자의 색으로,
마커 종류별로 다른 모양+라벨과 함께 합성하도록 확장했다. `XlsxExporter`는
`BaseMapImage`에 연결된 모든 `RouteLine`(최대 2개)을 가져와서 한 번에
합성한다.

## 아직 남은 것
- 마커 라벨이 원본 데이터와 어긋나지 않는지(스냅샷 방식의 한계) 실사용 확인
- 여전히 신설/철거 각 1줄까지만 — 같은 공종 내 여러 개별 선(예: 신설 케이블이
  두 개 이상 서로 다른 경로)까지는 지원 안 함

## 14단계 — `기별` 드롭다운 값 전면 수정 (실기기 테스트로 확보한 실제 목록 반영)

실기기 테스트 중 사용자가 실제 엑셀에서 AF/AC/AD/AE/BF/BH열의 드롭다운을
하나하나 캡처해서 보여줬다. 지금까지 가정한 "신설/철거" 이분법이 틀렸고
(실제로는 "이설"이 별도 항목), 코어수/포설방식/접속구분/안전조치도 전부
자유 텍스트가 아니라 통제된 목록이었다는 게 확인됐다. 반영 내용:

- **AF(작업구분)** — `FacilityPhase`(신설/철거) 대신 새 `WorkType` enum:
  신설/신설(공기압)/**이설**/이도조정/단순지장이설_케이블/신설(AD구간).
  지장이설 사업의 핵심 작업인 "이설"이 빠져있던 게 가장 큰 문제였다.
- **AC(케이블종류)** — Dry/가공/배선망/MSLT/리본형/관로/난연/세경관로 등
  확인됐지만 스크롤로 더 있어서 자유 텍스트 입력 유지 (틀릴 위험보다
  입력 못 하는 게 더 나쁘다고 판단).
- **AD(코어수)** — 자유 입력 대신 확인된 값(24/48/72/96/144/288) 중 선택.
- **AE(포설방식)** — 2개(가공/지중)가 아니라 4개: 가공/지중/입상/점가공.
- **BF(접속구분)** — 자유 텍스트 대신 확인된 11개 값 중 선택 (D-신설/
  여장정리/G-외피추가/D-외피추가/외피해체/FTTH신설/FTTH재접속/FTTH기설/
  MSLT신설/MSLT신설_FTTH/E_Type신설).
- **BH** — "방호차 필요 여부(체크박스)"로 잘못 이해하고 있었다. 실제로는
  안전조치 종류를 고르는 열이었다 (방호차/주간작업/이면도로/도로외부작업/
  인도내작업/능로/차량진입불가/공사장). `Boolean` → `SafetyMeasure?` enum으로
  교체.
- **AB(신규/재고)** — 신규/재고 정확히 2개, 기존 매핑 그대로 맞았음(확인만).

값 개수가 많은 필드(작업구분/코어수/포설방식/접속구분/안전조치)는 라디오
버튼 대신 "탭하면 선택 다이얼로그가 뜨는 텍스트" 패턴으로 화면을 바꿨다.
DB 버전 3 → 4.

실제 원가계산 결과 시트(`내역서_일반`)도 캡처해줘서, BH="방호차" 매핑이
실제 원가 항목("(안전)단방향 위험도로 교통안전(방호용)")으로 정확히
연결되는 것까지 확인했다.

**범위 밖으로 유지한 것**: RACK설치/광스플리터/광점퍼코드/성단/견인선포설/
내관포설/반경철관/타사시설물/GIS입력구분 등 — 실제 현장 데이터에서 전부
빈 칸이었던 열들이라 지장이설 사업엔 안 쓰이는 것으로 보고 손대지 않았다.

빌드 검증: `BUILD SUCCESSFUL`.

## 추가 발견 — 실제 개황도 범례 (실기기 테스트로 확보)

사용자가 실제 파일의 "범례" 영역을 캡처해줘서 정확한 색상/모양 체계를 확인했다.
지금 `DiagramCompositor`/`RouteEditorView`가 쓰는 색상(빨강 고정)은 이 범례와
다르다 — 다음 작업에서 아래 기준으로 맞출 것:

**선(케이블 경로):**
- 가공신설=빨간 점선, 가공기설=빨간 실선
- 지중신설=파란 점선, 지중기설=파란 실선
- FTTH신설=자홍 점선, FTTH기설=자홍 실선
- 케이블철거=검은 실선
- SKB 케이블=초록 실선
- T/B공동 케이블: 신설=노란 점선, 기설=노란 실선
- 임차케이블=주황 파선, 단순이설(케이블)=주황 파선(다른 패턴)

**점(함체/전주/맨홀):**
- 함체: 신설=파랑P, 기설=노랑P, 철거=검정P, SKB=초록P
- Master/Slave: 신설=파랑M/S, 기설=노랑M/S, 철거=검정M/S
- 전주(자가): 기설=자홍C, 신설=파랑C, 철거=검정C
- 전주(한전): 기설=C, 신설=빨간 점, 철거=검정 점 / 타사전주=초록, 타사전주(철거)=검정C
- 맨홀(자가): 기설=자홍M, 신설=파랑M, 철거=검정M / 타사맨홀=초록M

즉 색상은 "신설/기설/철거"를 나타내고, 모양(P/M/S/C)은 시설물 종류를 나타내는
2축 체계다. 지금 10단계 `WorkType`이 신설/기설/철거 3구분과 정확히 안 맞는
점도 이 범례와 맞춰 재검토 필요.
